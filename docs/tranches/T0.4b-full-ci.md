## Success criterion

1. **The app assembles**: a step of `app-check` assembles the test variant (`expo export`); red when assembling fails, seen on a throwaway pull request with a fault only the assembler sees (an imported image that does not exist).
2. **The version goes up**: a `version-check` job is red when a pull request changes the app without raising the version above the one of its base.
3. **Repository tools are tested on GitHub**: every `tools/dev/*.test.mjs` (audit, stop signals, stop gate, version check) runs in `version-check`.
4. `version-check` is required on `main` (`tools/dev/github-settings.sh`).

## In

- `app-check`, step « Assemble the app »: `expo export` of the test variant (`APP_VARIANT=preview`, Android) into `$RUNNER_TEMP`, with `EXPO_NO_TELEMETRY=1`, `EXPO_OFFLINE=1`, no source maps, no artifact uploaded, no token. Proves Metro assembles the variant that instant updates publish; does not prove the app starts, nor that a native module is in the APK (that is the trial and the native version).
- `tools/dev/check-version-bump.mjs` and its tests, closed by default: every `app/**` file counts except tests, `__mocks__/`, `jest.setup.*`, `app/src/tools/**`, `*.md`, ESLint and Prettier config, `.nvmrc`; in `app/package.json` only `devDependencies`, `jest` and scripts that run neither at install nor at build are ignored; in `app/package-lock.json` only dev entries. `app/eas.json` counts. Strictly greater, `x.y.z`; unreadable `package.json` → red.
- Job `version-check`: no path filter; on `main` pushes and on Mondays it only runs the tool tests. Limit written: with `strict: false`, a `main` that moved after the run is not checked again.
- `tools/dev/github-settings.sh`: `version-check` added to the required checks; diff before/after in the pull request.

## Risks

| Risk | Answer |
| --- | --- |
| `expo export` reaches the network or uploads something | `EXPO_OFFLINE=1`, no token, no artifact, `persist-credentials: false`, read-only token |
| A pull request edits the version check to pass itself | Inherent to `pull_request`; the security pass reads changes to checks line by line (`docs/SECURITE.md`) |
| A file that ships is wrongly ignored | Closed by default: only the listed exceptions are ignored; tested |

No data, no permission, no dependency added.

## Tests

`check-version-bump.mjs` (`node --test`): code changed without bump → red; with bump → green; equal, lower or malformed → red; only tests, tools, docs, lint/format config, dev dependencies or scripts → green; production dependencies, production lock entries, `eas.json` → bump required; the bump alone is not a change. Assembling: green on this pull request; red on a throwaway draft pull request with a missing image, closed without merging.

## Security pass and review (on commit 2425849)

- **Version check**: a renamed shipped file (moved to `app/src/tools/` or renamed `*.test.ts`) passed green → `--no-renames`; an accented file name was quoted by git and skipped → `-z`, raw names, and any name outside `app/` makes the run unusable; install and build scripts (`postinstall`, `prepare`, `eas-build-*`…) and `app/.npmrc` now count; test patterns anchored to code files; a base `package.json` without a version is unusable; the summary write cannot crash the run; compared with the first parent of the merge commit (the current `main`) instead of the event's base. 11 tests, three end to end on a temporary git repository.
- **Stop gate**: reads again `x=$(…)`, backticks, a command on the opener line of a here-document, an empty here-document; also reads `sh -c`/`bash -c`, `eval` and a here-document fed to a shell; blocks merge arguments read from input (`xargs`, `<`, `<<<`); newlines now separate commands. Limits written in its header and in `docs/SECURITE.md`.
