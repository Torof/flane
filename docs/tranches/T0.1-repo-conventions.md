**Jalon** : J0 — L'atelier est prêt

**Validée le** : 2026-10-20 (fiche redécoupée, D-017, D-018 ; puis D-019 : passage en public dans la tranche)

## Objectif

À la fin, le dépôt refuse de lui-même les erreurs les plus coûteuses : secret enregistré, message de commit hors format, modification directe de `main` ou contournement des hooks. Le dépôt est public sous AGPL-3.0, et GitHub est réglé pour protéger `main`, chercher les secrets, signaler les failles et recevoir les retours. Le kit Claude (démarrage automatique, liste d'autorisations) est sorti en T0.1b.

## Critère de réussite

L'utilisateur, sur son poste et sur GitHub, constate que :

1. `tools/dev/test-hooks.sh` passe au vert. Il prouve, dans un dépôt temporaire, que : un message de commit mal formé est refusé ; un commit contenant une fausse clé fabriquée à l'exécution est refusé, en citant la règle gitleaks déclenchée ; le garde-fou de Claude bloque un commit sur `main` et un `--no-verify` (même abrégé), demande tout push forcé, suit un changement de branche dans la même commande, et laisse passer un commit sur une branche dont le message contient « git commit ».
2. Une pull request ouverte sur GitHub présente le modèle avec la définition de « fini » en cases à cocher et le champ « fiche de tranche ». (Le modèle ne s'applique qu'une fois présent sur `main` : la PR de cette tranche a son corps collé à la main.)
3. Le dépôt est public, avec `LICENSE` AGPL-3.0 ; la fusion se fait par merge uniquement, la branche est supprimée après fusion ; les alertes de vulnérabilité, les correctifs de sécurité automatiques, la recherche de secrets et le blocage des push contenant un secret sont activés.
4. Une règle GitHub protège `main` : pas de push direct, pas de push forcé, pas de suppression. Vérifié par une tentative de push vers `main` depuis une branche, refusée par GitHub.
5. L'historique ne porte qu'une identité, anonyme.

## Dedans

**Avant la branche : historique anonymisé** (dépôt encore privé). Auteur et validateur des commits existants réécrits vers l'adresse anonyme GitHub. Le push forcé de `main` qui en résulte est fait par Claude, avec confirmation explicite de l'utilisateur dans l'outil : le garde-fou **demande** tout push forcé, il ne le bloque pas. Exception consignée dans le journal. Après le passage en public, la règle GitHub sur `main` interdit tout push forcé côté serveur, sans contournement possible.

**Licence et décisions**

**Hooks git locaux (`.githooks/`)**, règle commune : *en cas de doute, on bloque*.
- `commit-msg` : `^(feat|fix|docs|test|refactor|chore|perf)\((T[0-9]+\.[0-9]+[a-z]?|meta)\)!?: .+` ; exceptions précises : `^Revert "` et `^Merge (branch|pull request #[0-9]+) `. `fixup!` et `squash!` refusés (pas de rebase interactif dans la méthode).
- `pre-commit` : gitleaks 8.30.1 (`gitleaks git --pre-commit --staged`, rapport JSON lu sans jamais afficher le secret). gitleaks cherché dans le `PATH` puis `~/.local/bin`. Absent : refus avec le mode d'emploi. Aucun `.gitleaksignore` ni `gitleaks:allow` sans justification écrite dans le commit.
- `pre-push` : si `app/package.json` existe, types, lint et tests ; sinon sortie 0. Actif de fait à partir de T0.3.
- `tools/dev/setup.sh` : active `core.hooksPath`, installe gitleaks dans `~/.local/bin` depuis la version épinglée (Linux x64 seulement, refus propre sinon), somme de contrôle SHA-256 vérifiée, affiche l'état. Lancé par `/installation` et rappelé dans `README.md`.
- `tools/dev/test-hooks.sh` : tous les cas du plan de tests, dans un dépôt git temporaire ; la fausse clé est assemblée à l'exécution, jamais écrite en clair.
- `.editorconfig` : UTF-8, LF, deux espaces, fin de fichier.

**Garde-fou de Claude (`.claude/hooks/garde-branche-main.sh` et `.py`)**, durci et fermé par défaut :
- Enveloppe bash qui convertit toute panne (python3 absent, exception, délai) en blocage : la version actuelle de Claude Code laisse passer l'appel si un hook échoue autrement.
- Analyse en python (bibliothèque standard) : extraction du JSON, retrait des heredocs, découpage en segments avec guillemets, redirections ; un segment non analysable : bloqué.
- Trois décisions : bloquer, autoriser, ou **demander** à l'utilisateur (sortie JSON du hook).
- Bloqué partout : `HEAD:main`, `:main` (push non forcé vers `main` : passer par une pull request), `--no-verify`, `-n` sur commit, push et merge, `-c core.hooksPath`, `git branch -f main`, `update-ref`, `filter-branch`, `gh api` en écriture sur `contents`, `git/refs`, `merges` ; variables `GIT_*` ou `GH_*` définies ou exportées ; écriture par Bash dans `.claude/`, `.githooks/`, `.github/`, `.git/`, `tools/dev/`, y compris par `awk`, `sed w`, `sort -o`, `find -fprint`, ou vers un chemin dynamique (`$D/x`, accolades). Les options longues abrégées (`--no-veri`, `--force-w`) sont reconnues.
- Bloqué sur `main` : `commit`, `merge`, `rebase`, `cherry-pick`, `reset`, `push` sans refspec. La branche est lue depuis le `cwd` de l'appel, puis suivie segment par segment : `cd`, `checkout` et `switch` dans la même commande sont pris en compte.
- Interpréteurs (`bash`, `sh`, `python3`, `node`) : un script du projet (dossiers protégés) s'exécute librement ; un script bash passé en heredoc est analysé comme la commande ; tout autre programme (en ligne, sur l'entrée standard, fichier hors projet) est demandé s'il mentionne git ou un dossier protégé. Limite connue, consignée dans `docs/SECURITE.md` : un script externe peut faire n'importe quoi une fois confirmé.
- Demandé (confirmation de l'utilisateur) : push forcé, à consigner dans le journal ; `bash -c`, `eval`, `$(…)` combinés à `git` ou `gh` ; toute écriture `gh api` non interdite ; `gh pr merge` (porte Intégrer) ; `gh repo edit`.
- Le faux positif actuel (texte contenant « git commit ») disparaît ; un nouveau faux positif reste acceptable, un faux négatif non. Le bit exécutable des scripts se pose par `git update-index --chmod=+x`.

**`.claude/settings.json`** : `ask` étendu à `Write` et `Edit` sur `.claude/**`, `.githooks/**`, `.github/**`, `tools/dev/**`. Pas de liste `allow` (T0.1b).

## Approche

Scripts bash et python (bibliothèque standard), fichiers de configuration, sans paquet npm. Ordre : `test-hooks.sh` et hooks git (le plus risqué, écrit en premier avec ses tests), garde-fou durci (même banc de tests), `setup.sh`, modèles GitHub, passage en public et réglages, documentation. Les réglages GitHub sont relus après écriture.

## Risques de sécurité

| Risque | Parade |
| --- | --- |
| Hooks locaux contournés (`--no-verify`, clone sans `setup.sh`) | Garde-fou de Claude bloque `--no-verify` ; mêmes contrôles dans les vérifications automatiques en T0.2 ; `README.md` et `/installation` rappellent `setup.sh` |
| Garde-fou avec faux négatifs, ou en panne | Règle « en cas de doute, on bloque » ; enveloppe qui convertit toute panne en blocage ; liste de contournements connus ; tests négatifs et positifs |
| Claude affaiblit ses propres garde-fous en autonomie | `ask` sur `Write` et `Edit` de `.claude/**`, `.githooks/**`, `tools/dev/**` ; écriture par Bash vers ces chemins bloquée |
| Exécutable gitleaks compromis | Version épinglée, SHA-256 vérifié, HTTPS depuis les versions officielles |
| Fausse clé de test détectée comme vraie, ou jamais détectée | Clé assemblée à l'exécution ; test qui vérifie le nom de la règle déclenchée |
| Dépôt public : issues ouvertes à tous | Jamais le corps d'une issue dans le contexte de Claude (T0.1b) ; modèles qui n'invitent à aucune position |
| Dépôt public : nom non déposé | Dépôt de marque INPI, question ouverte au backlog ; risque ajouté à `SECURITE.md` |
| Courriel ou identité personnelle dans l'historique public | Historique réécrit avant le passage en public ; réglage GitHub « adresse privée » côté utilisateur |
| Règle GitHub qui bloque toute fusion | Règle minimale sans vérification exigée ; relecture après création |
