# T0.3 — Squelette de l'appli Expo

**Jalon** : J0 — L'atelier est prêt
**Étape du cycle** : Observer
**Statut dans le backlog** : À tester sur la route
**Budget** : 2 sessions
**Branche** : `feat/T0.3-app-skeleton`
**Validée le** : 2026-10-20 (porte Choisir ; l'utilisateur précise qu'il a un abonnement EAS payant : pas de file d'attente ni de quota à surveiller)

## Objectif

Une appli « Flâne » vide, en français, s'installe sur le téléphone de l'utilisateur et s'ouvre sur trois onglets sans contenu. Le dépôt contient tout ce qu'il faut pour coder la suite : TypeScript strict, lint, formatage, tests, fichiers de traduction, structure des dossiers, compilation dans le nuage.

## Critère de réussite

1. L'utilisateur télécharge l'APK du profil **`preview`** produit par EAS Build (code embarqué, sans serveur de développement), l'installe sur son Android, ouvre « Flâne (dev) » et voit trois onglets : **Trajet**, **Préférences**, **À propos**. Chaque onglet affiche un titre et une phrase en français. L'onglet « À propos » affiche la version, la licence (AGPL-3.0), l'adresse du dépôt source (en texte) et la mention « © les contributeurs d'OpenStreetMap » (obligation ODbL, placée dès maintenant). L'appli s'ouvre aussi en mode avion.
2. Dans `app/`, `npm run check` passe au vert : types, lint sans aucun avertissement, formatage, tests, notices SPDX.
3. Le manifeste de l'APK `preview` ne déclare que les permissions de cette liste : `android.permission.INTERNET`, et la permission interne qu'androidx déclare pour l'appli elle-même (`<identifiant>.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`). Toute autre permission apparue est retirée par `android.blockedPermissions`. Aucun appel réseau (`fetch`, `XMLHttpRequest`, `WebSocket`) dans `app/src/`.
   *Constaté à la construction* (manifeste décodé depuis l'APK, pas par simple recherche de chaînes) : la première compilation déclarait aussi `READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE`, `SYSTEM_ALERT_WINDOW` et `VIBRATE`, ajoutées par les réglages par défaut d'Expo malgré `permissions: []` ; elles sont bloquées. Le manifeste contient aussi : le schéma `exp+flane` à côté de `flane` (ajouté par Expo pour ses liens de développement, inoffensif, aucun paramètre n'est lu) ; un récepteur exporté `androidx.profileinstaller.ProfileInstallReceiver`, standard d'androidx, protégé par la permission système `DUMP` ; une requête de visibilité de paquet pour le schéma `https`. Le client de développement (`development`) déclare en plus `ACCESS_NETWORK_STATE`, `ACCESS_LOCAL_NETWORK`, `CHANGE_WIFI_MULTICAST_STATE`, le mode débogage et le trafic en clair, nécessaires pour parler à Metro : ils ne concernent pas le critère.

## Dedans

- Projet Expo (SDK 58) dans `app/`, TypeScript strict (`noUncheckedIndexedAccess`, `@typescript-eslint/no-explicit-any` en erreur), nom affiché « Flâne », schéma d'URL `flane`.
- **Deux variantes** par `app.config.ts` : `development` et `preview` → identifiant `app.flane.dev`, nom « Flâne (dev) » ; `production` (non construite ici) → `app.flane`, « Flâne ». Ainsi la version de développement et la version publiée (T5.4) cohabiteront sur le même téléphone, et `app.flane` (D-015) reste vierge jusqu'à la publication.
- Navigation par onglets avec Expo Router. Règle fixée : `app/src/app/` ne contient que des **routes minces** (un fichier par onglet, qui réexporte un écran) ; les écrans et composants vivent dans `app/src/ui/`, conformément à `docs/CONVENTIONS.md`, qui est précisé en ce sens.
- Structure des dossiers de `docs/CONVENTIONS.md` créée (`domain/`, `engine/`, `data/`, `services/`, `ui/`, `i18n/`, `config/`), avec un `README.md` d'une ligne dans chaque dossier vide.
- Traductions : `src/i18n/fr.json` (clés plates) et une fonction `t(key)` maison, typée sur les clés du fichier. Aucun texte affiché en dur. Pas d'interpolation de variables ni de détection de la langue du téléphone pour l'instant.
- Règle d'architecture ESLint : depuis `src/domain/` et `src/engine/`, interdiction d'importer `react`, `react-native`, `expo*`, `src/app`, `src/ui`, `src/services`. Vérifiée à la construction par un fichier d'essai (lint en échec), consigné dans la PR.
- Outils : ESLint (`eslint-config-expo`, `--max-warnings 0`, `no-console` en erreur), Prettier, Jest (`jest-expo`) avec Testing Library ; scripts `typecheck`, `lint`, `format`, `format:check`, `test`, `spdx`, `check` (tout enchaîné). Le hook `pre-push` appelle désormais `npm run check`.
- Notice `// SPDX-License-Identifier: AGPL-3.0-or-later` en tête de chaque fichier de code : extensions `.ts`, `.tsx`, `.js`, `.mjs`, `.cjs`, `.sh` ; dossiers exclus `node_modules`, `android`, `ios`, `.expo`, `dist`, `coverage` ; fichiers de déclaration exclus (`*.d.ts`, générés ou copiés) ; après le shebang pour les scripts. Les scripts existants (`.githooks/*`, `tools/dev/*.sh`) reçoivent la notice. Script maison `tools/dev/check-spdx.sh`, testé par un test Jest qui le lance sur un dossier temporaire.
- `.npmrc` (`ignore-scripts=true`, `save-exact=true`), `.nvmrc` (Node 24.22.0 : Node 22.15.0, installé sur le PC, ne retrouve pas ses modules dans un chemin qui contient un accent, « Flâne » ; `setup.sh` installe la bonne version par nvm), `package-lock.json` enregistré. `.gitignore` racine complété : `node_modules/`, `.expo/`, `android/`, `ios/`, `dist/`, `coverage/`, `expo-env.d.ts`, `*.tsbuildinfo`, `*.apk`, `*.aab`, `*.keystore`, `*.jks`, `credentials.json`, `credentials/`.
- EAS : `eas.json` avec trois profils, `development` (client de développement), `preview` (APK autonome, distribution interne) et `production` (déclaré sans source de clé : il ne peut pas être construit avant que T5.4 crée le keystore de publication, ce qui empêche de signer `app.flane` avec la clé de dev), version de Node alignée sur `.nvmrc`. **Keystore de développement généré localement** par `keytool` (Java déjà présent), fourni à EAS par `credentials.json` (`credentialsSource: local`), tous deux hors dépôt. Identifiant de projet EAS (un UUID) dans `app.config.ts`. Les deux profils sont compilés dans cette tranche : `preview` pour la porte Observer, `development` pour les sessions de code à venir. L'utilisateur a un abonnement EAS payant : pas de file d'attente ni de quota à surveiller.
- Inventaire ponctuel des licences des dépendances de production par un script maison `tools/dev/licenses.mjs` (lit `node_modules`, sans dépendance), collé dans la PR. Règle `npm audit`, réécrite après l'audit : aucune alerte haute ou critique dans du code embarqué dans l'APK ; les alertes de l'outillage tiré par `expo` (CLI, Metro) et des outils de développement sont listées dans la PR avec leur chaîne `npm explain`. La règle d'origine (« aucune haute dans `--omit=dev` ») était inapplicable : `npm` compte la CLI d'Expo comme dépendance de production.
- Télémétrie d'Expo CLI et d'EAS CLI : `EXPO_NO_TELEMETRY=1` en préfixe des scripts npm et des commandes `eas` lancées par Claude ; documentée dans le README pour le shell de l'utilisateur.
- `README.md` du dépôt : installer, lancer, compiler, installer l'APK. `docs/CONVENTIONS.md` (routes minces, scripts npm), `docs/GLOSSAIRE.md` (client de développement, onglet, variante), `docs/ARCHITECTURE.md` si nécessaire.
- Tests : `t()` (clé connue ; clé manquante via `@ts-expect-error`, renvoie la clé sans exception) ; rendu de chaque écran (titre présent) ; script SPDX (fichier sans notice détecté, fichier avec shebang accepté).

## Dehors

- Tout contenu fonctionnel des onglets : jalons 1 et 2.
- Carte, MapLibre (D-007) : à sa première utilisation.
- Vérifications automatiques GitHub Actions et règle « vérifications exigées » sur `main` : **T0.2**.
- Historique des versions, étiquette `v0.0.1` : **T0.4**.
- Compilation de production, keystore de publication, Google Play : **T5.4**.
- Compilation locale (SDK Android complet) : parking.
- Nettoyage de `.claude/settings.local.json` : hors tranche (fichier ignoré par git, réglages de Claude : à faire par l'utilisateur ou sur une branche `docs/meta` avec son accord).
- Mode sombre, orientation paysage : parking (appli en clair et en portrait pour l'instant ; le mode nuit comptera pour la conduite, à traiter avec la vue en mouvement, jalon 3).
- Détection de la langue du téléphone, anglais : parking.
- Icône et écran de démarrage définitifs : parking (icône du modèle Expo conservée).
- Interpolation dans les traductions (distances, durées) : première tranche qui en a besoin.
- Mises à jour à distance (`expo-updates`) : non voulues, pas installées.
- iOS : plus tard ; rien de spécifique, rien qui l'empêche.

## Approche

- Installation sans exécution de script : `npm pack expo-template-blank-typescript@sdk-58` (version épinglée, extraction sans installation), fichiers copiés dans `app/`, puis `.npmrc` écrit **avant** le premier `npm install`. Pas de `create-expo-app@latest`. Si une dépendance exige un script d'installation, elle est nommée dans la PR et reconstruite explicitement (`npm rebuild <paquet>`).
- `app/src/app/_layout.tsx` (racine), `app/src/app/(tabs)/_layout.tsx` (onglets, `tabBarIcon` neutralisé, libellés texte), `index.tsx` (Trajet, route par défaut), `preferences.tsx`, `about.tsx` (routes minces). Écrans dans `app/src/ui/screens/`.
- `app/src/i18n/fr.json` + `app/src/i18n/t.ts` : `t<K extends keyof typeof fr>(key: K): string`. À l'exécution, une clé manquante renvoie la clé, sans journalisation.
- `app.config.ts` : variante par `process.env.APP_VARIANT` (`development` par défaut) ; `android.package`, `name`, `version` lue depuis `package.json`, `scheme: "flane"`, `orientation: "portrait"`, `userInterfaceStyle: "light"`, `android.permissions: []`, `android.blockedPermissions` selon le manifeste constaté, `android.allowBackup: false` (ajouté sur constat de l'audit : la sauvegarde Android copierait les données privées sur Google Drive), pas de `updates`. `newArchEnabled` n'existe plus au SDK 58 (toujours actif) ; `expo-doctor` 1.21.5 : 20 vérifications passées.
- Version affichée dans « À propos » : lue depuis la configuration (`expo-constants`), jamais copiée dans `fr.json`.
- Vérification du manifeste sans SDK Android : l'APK est une archive zip ; son `AndroidManifest.xml` binaire est décodé par un petit script Python maison (format AXML : table de chaînes, balises, attributs typés), car la simple recherche de chaînes ne distingue pas une permission déclarée d'une permission retirée. Résultat collé dans la PR.
- Ordre de construction : squelette et outils → tests verts → `eas project:init --non-interactive` → keystore local → `eas build --profile preview --non-interactive` puis `--profile development` → vérification du manifeste → audit et relecture pendant l'attente → PR avec le lien de l'APK. La PR reste « ne fusionnez pas encore » tant que l'APK n'est pas vérifié.

## Plan de tests

- Cas nominal : `npm run check` vert ; APK `preview` installé, trois onglets, textes en français, version, licence, dépôt et mention OSM dans « À propos ».
- Cas limites : clé de traduction manquante (renvoie la clé, pas d'exception) ; fichier sans notice SPDX (échec attendu), script avec shebang (accepté) ; `npm ci` sur un clone neuf avec `ignore-scripts` ; import interdit depuis `src/domain/` (lint en échec).
- Hors ligne : APK `preview` ouvert en mode avion, les trois onglets s'affichent.
- Test sur le téléphone : installation de l'APK (sources inconnues autorisées pour ce fichier), ouverture, passage d'un onglet à l'autre, fermeture et réouverture.

## Prévoir sans construire

- Dossiers du domaine et du moteur créés, règle ESLint qui leur interdit l'interface et la plateforme : le principe d'architecture est outillé avant la première ligne de domaine.
- Routes minces : l'affichage pourra changer (vue conducteur, vue passager) sans toucher aux écrans.
- Traductions par fichier de langue : l'anglais s'ajoutera par un fichier.
- Onglet « À propos » : emplacement des mentions légales (ODbL, DATAtourisme, politique de confidentialité de T5.2).
- Variantes `dev` et `production` : la publication (T5.4) n'aura pas à renommer quoi que ce soit.
- Schéma `flane` : base des liens profonds (import de trajet, partage).
- Client de développement et profil `development` prêts pour les modules natifs.
- `tools/dev/licenses.mjs` et `check-spdx.sh` : repris par les vérifications automatiques de T0.2.
